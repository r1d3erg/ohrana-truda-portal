# СОУТ и ОПР: ручной ввод данных

Разделы портала **«СОУТ»** и **«ОПР»** заполняются вручную: по каждому офису
ведётся история проведённых и запланированных оценок. По введённым данным
портал считает сроки и формирует предупреждения. Они видны на страницах разделов,
на дашборде (блок «Сроки и нарушения») и в двух колонках тепловой карты.

> законодательства справочники и сроки правятся в `backend/app/registers.py`.

## 1. Какие данные вносятся и почему

Отбор полей шёл по вопросу «что проверяет инспектор и какие сроки можно
пропустить». Для СОУТ это:

| Что нужно контролировать | Норма | Какие данные для этого нужны |
|---|---|---|
| Плановая СОУТ не реже 1 раза в 5 лет | ч. 4 ст. 8 426-ФЗ; срок считается **со дня внесения сведений в ФГИС СОУТ** | дата утверждения отчёта, дата внесения в ФГИС, «действует до» |
| Внеплановая СОУТ в установленный срок | ст. 17 426-ФЗ: новые рабочие места — 12 месяцев; предписание ГИТ и другие основания — 6 месяцев | основание, дата наступления основания, срок проведения |
| Декларация освобождает от повторной СОУТ | ст. 11 426-ФЗ: на местах с классами 1–2 повторная СОУТ не требуется до обстоятельств ч. 5 ст. 11 | признак подачи декларации, номер и дата, признак прекращения |
| Ознакомление работников под подпись | ч. 5 ст. 15 426-ФЗ: не позднее 30 календарных дней с утверждения отчёта (информирование через Госуслуги его не заменяет) | дата завершения ознакомления, число ознакомленных |
| Размещение результатов на сайте (если сайт есть) | ст. 15 426-ФЗ: 30 дней с утверждения отчёта | дата размещения |
| Все рабочие места охвачены | аналогичные места: замеры на 20 %, но не менее 2, результат распространяется на все | всего мест, охвачено, из них аналогичных |
| Вредные условия и гарантии работникам | итоговые классы 3.1–4 | количество мест по каждому классу |
| Улучшение условий труда | перечень мероприятий по результатам СОУТ | мероприятий в плане / выполнено |
| Кто и как проводил | экспертная организация из реестра или **упрощённый порядок** (ПП РФ № 1830; с 01.09.2026 — для малого бизнеса 55 видов деятельности, приказ Минтруда № 345н) | порядок проведения, организация, номер в реестре, приказ о комиссии |

Для ОПР:

| Что нужно контролировать | Норма | Какие данные для этого нужны |
|---|---|---|
| ОПР проведена и регулярно пересматривается | ст. 214, 218 ТК РФ; **обязательная периодичность не установлена** — её определяет работодатель в своём положении | дата утверждения результатов, плановая дата пересмотра |
| Метод оценки выбран работодателем | приказ Минтруда № 776н (Примерное положение о СУОТ) | метод, кто проводил (своими силами или сторонняя организация), приказ о комиссии |
| Опасности выявлены по всем рабочим местам | перечень опасностей — приложение к № 776н | всего мест, оценено, должностей, выявлено опасностей |
| По средним и высоким рискам есть меры | план мероприятий; иерархия мер — от исключения опасности до СИЗ | количество рисков по уровням, дата утверждения плана, мероприятий в плане / выполнено |
| Работники проинформированы | ст. 214 ТК РФ | дата ознакомления |

Персональные данные (ФИО конкретных работников) и карты по каждому рабочему месту
сознательно не вносятся. Портал хранит сводку по офису, а первичные документы
остаются у работодателя и во ФГИС. Подробнее — в разделе 9.

| Порядок проведения | С экспертной организацией / В упрощённом порядке (ПП РФ № 1830) | да | |
| Статус | Запланирована / Проводится / Завершена | да | Действующей считается только завершённая |

| Организация, рег. номер в реестре | текст | нет | |
| Приказ о комиссии | текст («№ 12 от 10.02.2026») | нет | |
| Дата начала | дата | нет | |
| Утверждение отчёта | дата | **для завершённой** | От неё считаются 30 дней на ознакомление и размещение на сайте |
| Внесение сведений в ФГИС СОУТ | дата | нет | Не раньше утверждения отчёта |
| Действует до | дата | нет | Если пусто: дата ФГИС (или отчёта) + 5 лет |

| Классы 1, 2, 3.1, 3.2, 3.3, 3.4, 4 | целые ≥ 0 — число мест по итоговому классу | нет | Сумма ≤ охвачено |
| Декларация подана, дата, номер | флажок, дата, текст | нет | Только при наличии мест класса 1–2 |
| Декларация прекращена | флажок | нет | Отмечается при обстоятельствах ч. 5 ст. 11 |
| Ознакомление завершено, ознакомлено работников | дата, число | нет | |
| Размещено на сайте | дата | нет | |
| Мероприятий в плане / выполнено | целые ≥ 0 | нет | Выполнено ≤ в плане |
| Примечание | текст до 5000 символов | нет | |

Ошибки ввода, при которых запись не сохраняется: нет даты отчёта у завершённой
СОУТ; нет основания у внеплановой; отчёт раньше даты начала; ФГИС раньше
отчёта; превышения «охвачено > всего», «аналогичных > охвачено», «сумма классов >
охвачено», «выполнено > в плане»; декларация без мест класса 1–2. Все ошибки
показываются в форме разом.

## 3. СОУТ: сроки, статусы, предупреждения

**Действующая СОУТ офиса** — завершённая запись с самой поздней датой ФГИС (если
её нет — с самой поздней датой отчёта). Записи со статусом «Запланирована» или
«Проводится» отслеживаются отдельно, по сроку проведения.

| Статус офиса | Условие | Цвет |
|---|---|---|
| Действует | срок не истёк и до окончания больше `SOUT_WARN_DAYS` (180) дней | зелёный |
| Декларация, без повторной СОУТ | декларация подана и не прекращена, все охваченные места класса 1–2 | зелёный |
| Истекает срок | до окончания ≤ 180 дней | жёлтый |
| Срок истёк | «действует до» в прошлом (и нет действующей декларации) | красный |
| Только запланирована | завершённых нет, есть запланированные | жёлтый |
| Нет данных | записей нет | серый |

Если среди предупреждений есть критичное, офис подсвечивается красным при любом
статусе.

| Предупреждение | Когда | Уровень |
|---|---|---|
| Срок действия СОУТ истёк | статус «Срок истёк» | критичное |
| СОУТ действует до …, пора планировать новую | статус «Истекает срок» | внимание |
| Нет сведений о СОУТ | записей нет | внимание |
| Не завершено ознакомление работников (срок …) | прошло > 30 дней с отчёта, даты ознакомления нет | критичное |
| Результаты не размещены на сайте | прошло > 30 дней с отчёта, даты размещения нет | внимание |
| СОУТ охватывает X из Y рабочих мест | охвачено < всего | внимание |
| Декларация прекращена — нужна внеплановая СОУТ | флажок «прекращена» и нет запланированной внеплановой | критичное |
| Рабочих мест с вредными/опасными условиями: N | классы 3.1–4 > 0 | внимание |
| Просрочена внеплановая/плановая СОУТ: основание | запланированная или проводящаяся СОУТ, срок проведения прошёл | критичное |
| Запланирована … СОУТ до …: основание | запланированная, срок не прошёл | внимание |

## 5. ОПР: сроки, статусы, предупреждения

**Действующая ОПР офиса** — завершённая запись с самой поздней датой
утверждения.

| Статус офиса | Условие | Цвет |
|---|---|---|
| Действует | до пересмотра больше `OPR_WARN_DAYS` (60) дней | зелёный |
| Скоро пересмотр | до пересмотра ≤ 60 дней | жёлтый |
| Пересмотр просрочен | дата пересмотра в прошлом | красный |
| Только запланирована | завершённых нет, есть запланированные | жёлтый |
| Нет данных | записей нет | серый |

| Предупреждение | Когда | Уровень |
|---|---|---|
| Нет сведений об ОПР | завершённых записей нет | внимание |
| Пересмотр ОПР просрочен | статус «Пересмотр просрочен» | критичное |
| Плановый пересмотр до … | статус «Скоро пересмотр» | внимание |
| Есть средние/высокие риски, но не утверждён план мероприятий | средних или высоких > 0, даты плана нет | внимание |
| Высоких рисков: N (мероприятия X из Y) | высоких > 0; **критичное**, если мероприятий нет или выполнены не все | критичное / внимание |
| Работники не ознакомлены с результатами ОПР | даты ознакомления нет | внимание |
| ОПР охватывает X из Y рабочих мест | оценено < всего | внимание |

## 6. Как пользоваться

1. **СОУТ** или **ОПР** в меню. Вверху — счётчики по статусам: клик по счётчику
   фильтрует таблицу. Таблица показывает по каждому офису статус, срок,
   охват рабочих мест, классы условий (или уровни рисков) и число замечаний.
2. Клик по строке открывает **карточку офиса**: замечания со сроками, сведения
   о действующей оценке и историю всех записей.
3. **«+ СОУТ» / «+ ОПР»** открывает форму. Подсказки под полями сразу
   показывают, что посчитается автоматически: «действует до», срок
   внеплановой СОУТ, 30-дневный срок ознакомления, дату пересмотра ОПР.
4. **«Изменить»** в истории — правка записи, например, когда ознакомление
   завершилось или мероприятия выполнены. **«Удалить»** доступно роли
   «Супер-админ».
5. Запланированную внеплановую СОУТ (например, после открытия новых рабочих
   мест) заводите сразу со статусом «Запланирована» и датой основания: портал
   будет напоминать о сроке. Когда СОУТ проведена, смените статус на
   «Завершена» и заполните отчёт.
6. На **дашборде**: блок «СОУТ и ОПР по офисам» (клик — переход в раздел),
   «Сроки и нарушения» (клик по пункту — карточка офиса в нужном разделе) и
   колонки «СОУТ» и «ОПР» в тепловой карте.

## 7. Модель данных и API

Таблицы `sout_assessments` и `risk_assessments` (код —
`backend/app/models.py`) связаны с `offices` через `office_id`. При удалении
офиса записи удаляются каскадно. Таблицы создаются автоматически при
старте бэкенда; уже существующие таблицы при этом не меняются.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/sout`, `/api/opr` | Состояние по всем офисам: `state`, `state_label`, `level`, `current` (действующая запись), `pending` (запланированные), `alerts` |
| GET | `/api/offices/{code}/sout`, `/api/offices/{code}/opr` | То же по одному офису + `records` (вся история) |
| POST | `/api/offices/{code}/sout`, `/api/offices/{code}/opr` | Добавить запись (тело — поля из разделов 2 и 4, JSON) → 201 |
| PUT | `/api/sout/{id}`, `/api/opr/{id}` | Заменить запись целиком |
| DELETE | `/api/sout/{id}`, `/api/opr/{id}` | Удалить запись |
| GET | `/api/config` | Справочники (виды, основания со сроками, методы, статусы) и настройки сроков |
| GET | `/api/dashboard` → `registers` | `sout.counts`, `opr.counts`, `sout.harmful_workplaces`, `opr.high_risks`, `*.by_office`, `alerts` (до 30, критичные первыми), `alerts_total`, `alerts_bad` |

Ошибки проверки — `422` с `detail.errors` (список понятных сообщений), как и
при загрузке чек-листа.

Пример — завершённая плановая СОУТ:

```bash
curl -X POST http://localhost:8080/api/offices/cy1/sout \
  -H 'Content-Type: application/json' \
  -d '{"report_date":"2026-03-01","fgis_date":"2026-03-10","contractor":"ООО «Оценка»",
       "workplaces_total":40,"workplaces_assessed":40,"analogous_workplaces":32,
       "class_2":40,"declaration_submitted":true,"familiarized_date":"2026-03-20"}'
# → valid_until: 2031-03-10, статус офиса: «Декларация, без повторной СОУТ»
```

## 8. Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SOUT_VALIDITY_YEARS` | `5` | Срок действия результатов СОУТ |
| `SOUT_WARN_DAYS` | `180` | За сколько дней до окончания СОУТ предупреждать |
| `OPR_REVIEW_MONTHS` | `12` | Периодичность пересмотра ОПР по умолчанию — выставьте по своему положению |
| `OPR_WARN_DAYS` | `60` | За сколько дней до пересмотра ОПР предупреждать |

Справочники (основания и сроки внеплановой СОУТ, методы ОПР) находятся в
`backend/app/registers.py`.

## 9. Что можно добавить дальше

- **Карты СОУТ и ОПР по рабочим местам**: должность, количество работников,
  класс и факторы (шум, освещение, микроклимат…), гарантии и компенсации,
  рекомендации по СИЗ. Сейчас хранится сводка по офису.
- **Перечень мероприятий** с ответственными и сроками вместо счётчиков
  «в плане / выполнено».
- **Загрузка файлов** (отчёт, декларация, приказ о комиссии) или ссылки на них.
- **Импорт из Excel** реестра СОУТ, по аналогии со сводной таблицей.
- **Уведомления** ответственным о приближении сроков.
- Связь с чек-листом: например, отмечать «Отчёт о СОУТ» как «Есть», когда в
  разделе СОУТ есть действующая запись.
