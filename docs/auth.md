# Авторизация и роли

Уровень — «обычный»: вход по логину и паролю, серверные сессии, роли с проверкой на бэкенде.
Вход через Active Directory / SSO — следующий этап (см. «Что дальше»).

## Роли

| Роль | Кто | Видит | Может изменять |
| --- | --- | --- | --- |
| `admin` — Служба охраны труда | Специалист / служба ОТ | Всё | Всё: пользователи и роли, офисы и ответственные, загрузка чек-листа по любому офису, СОУТ, ОПР, ПБ, ЭБ, ГО ЧС, удаление загрузок и записей |
| `responsible` — Ответственный офиса | Ответственный за ОТ в офисе | Все офисы (для сравнения) | Только свои офисы: загрузка чек-листа, добавление и правка СОУТ и ОПР, карточки ПБ, ЭБ, ГО ЧС. Удалять и создавать офисы не может |
| `viewer` — Руководитель | Руководитель компании или офиса | Всё | Ничего (только просмотр) |

Офисы ответственного назначает администратор на странице «Пользователи и роли».
Если в загружаемой таблице офис, которого ещё нет в портале, создать его может только `admin`.

Права проверяет **бэкенд** (`backend/app/auth.py`, зависимости `current_user`, `require_editor`,
`require_admin`, `ensure_office_access`). Фронтенд только прячет недоступные кнопки.

## Как устроен вход

| Что | Как |
| --- | --- |
| Пароли | `hashlib.scrypt` (N=2^14, r=8, p=1, соль 16 байт) — без внешних зависимостей |
| Требования к паролю | не короче 10 символов, не только буквы и не только цифры, не равен логину |
| Сессия | случайный токен 256 бит в cookie `ot_session`: `HttpOnly`, `SameSite=Strict`, `Path=/api`, `Secure` при `COOKIE_SECURE=true`. В БД (`auth_sessions`) хранится только SHA-256 токена |
| Срок | не дольше `SESSION_HOURS` (12 ч) и выход после `SESSION_IDLE_MIN` (120 мин) бездействия |
| CSRF | изменяющие запросы (POST/PUT/PATCH/DELETE) принимаются только с заголовком `X-Requested-With: ot-portal` + `SameSite=Strict` |
| Перебор паролей | после `LOGIN_MAX_FAILS` (5) неудачных попыток с одного IP или на один логин — блок на `LOGIN_WINDOW_MIN` (15) мин. Ответ на неверный логин и неверный пароль одинаковый |
| Временный пароль | при создании пользователя и сбросе пароля — флаг `must_change_password`: до смены пароля доступны только `/auth/me`, `/auth/password`, `/auth/logout` |
| Отключение и сброс | блокировка пользователя или сброс пароля сразу закрывают все его сессии; смена своего пароля закрывает остальные сессии |
| Журнал | вход, неудачные попытки, создание и изменение пользователей пишутся в лог бэкенда (`ohrana.auth`) |

## Первый администратор

При запуске, если в БД нет ни одного пользователя, создаётся администратор `ADMIN_LOGIN` (по умолчанию `admin`):

- пароль из `ADMIN_PASSWORD`, если задан;
- иначе пароль генерируется и **один раз** выводится в лог бэкенда
  (локально — в окне Терминала `start-dev.command`, в Docker — `docker compose logs backend`).

При первом входе пароль нужно сменить. Дальше пользователи создаются в портале: «Администрирование → Пользователи и роли».

## API

| Метод | Путь | Кто | Назначение |
| --- | --- | --- | --- |
| POST | `/api/auth/login` | все | `{login, password}` → пользователь + cookie |
| POST | `/api/auth/logout` | все | Закрыть сессию |
| GET | `/api/auth/me` | вошедший | Текущий пользователь: роль, офисы, `must_change_password` |
| POST | `/api/auth/password` | вошедший | `{current_password, new_password}` |
| GET | `/api/roles` | вошедший | Роли и подписи |
| GET | `/api/users` | admin | Список пользователей (без хэшей паролей) |
| POST | `/api/users` | admin | `{login, full_name, role, password, offices[]}` |
| PATCH | `/api/users/{id}` | admin | `full_name`, `role`, `offices`, `is_active`, `password` (сброс) |

Ответы: `401` — нужен вход, `403` — нет прав или нет заголовка CSRF, `429` — слишком много попыток входа.
Открытыми остаются только `/api/health` и `/api/config` (подписи и пороги, без данных).

Пример из командной строки:

```bash
H='X-Requested-With: ot-portal'
curl -c jar -H "$H" -H 'Content-Type: application/json' \
     -d '{"login":"admin","password":"..."}' http://localhost:8080/api/auth/login
curl -b jar -H "$H" -F file=@cy1.xlsx http://localhost:8080/api/imports
```

## Настройки (переменные окружения)

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` | `admin` / пусто | Первый администратор |
| `COOKIE_SECURE` | `false` | `true`, если портал работает по HTTPS |
| `SESSION_HOURS` / `SESSION_IDLE_MIN` | 12 / 120 | Срок сессии и выход по бездействию |
| `LOGIN_MAX_FAILS` / `LOGIN_WINDOW_MIN` | 5 / 15 | Ограничение попыток входа |
| `TRUST_PROXY` | `false` (в Docker — `true`) | Брать IP клиента из `X-Real-IP` (его выставляет nginx портала) |
| `API_DOCS` | `true` (в `.env.example` — `false`) | Swagger UI на `/api/docs` |

## Что дальше

- Вход через Active Directory (LDAP/Kerberos или SSO через OIDC) с назначением роли по группе AD.
- Журнал действий в БД (кто загрузил таблицу, кто изменил запись).
- Ограничение попыток входа в общем хранилище (Redis), если бэкенд будет работать в нескольких процессах.
